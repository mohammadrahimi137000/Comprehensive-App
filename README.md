# برنامه جامع | Comprehensive-App

برنامه دسکتاپ ویندوزی برای شناسایی بصری پنجره‌های نمودار، دریافت تیک XAUUSD از BiQuote، ساخت کندل‌های چندتایم‌فریمی، تحلیل OHLC، ثبت ژورنال و نگهداری محلی تاریخچه.

## قابلیت‌های پیاده‌سازی‌شده در شاخه توسعه

- پایش خودکار پنجره‌های قابل مشاهده ویندوز و تشخیص احتمالی نمودار با OpenCV.
- استخراج ROI و هندسه کندل؛ OCR اختیاری برای نماد/تایم‌فریم و قیمت‌های محور، تبدیل پیکسل به OHLC تخمینی فقط پس از کالیبراسیون.
- اتصال SignalR به BiQuote برای تیک XAUUSD؛ ذخیره کندل‌های کامل M1/M5/M10/M15/H1/H4 در SQLite.
- اعتبارسنجی تازگی و کیفیت Quote؛ رد داده قدیمی، شبیه‌سازی‌شده یا نامعتبر.
- SignalR با fallback محدود REST؛ bootstrap تاریخچه OHLC بسته‌شده از BiQuote؛ پایش مرجع XAUS/Corgano فقط هنگام وجود Quote بروکر تازه و بدون جایگزینی Bid/Ask.
- مغزهای مستقل تکنیکال، پرایس‌اکشن، آمار نوسان و proxy نقدینگی؛ زون‌های حمایت/مقاومت و سناریوهای ۱۵ دقیقه‌ای.
- ذخیره snapshot پیش‌بینی‌ها، ژورنال دستی، ذخیره تصویر پنجره چارت و گزارش عملکرد بر حسب R.
- Overlay شفاف و mouse-through با بازکالیبراسیون دوره‌ای؛ فقط در صورت تشخیص XAUUSD/M1، OCR محور قیمت و فاصله‌گذاری منظم کندل‌ها.

## نصب و اجرا (Windows 10/11)

نسخه‌ای که CI روی آن آزمایش می‌شود Python 3.12 است. سازگاری Python 3.15 هنوز تأیید نشده است.

```powershell
git clone https://github.com/mohammadrahimi137000/Comprehensive-App.git
cd Comprehensive-App
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python main.py
```

## تست

```powershell
python -m pytest -q
```

## مواردی که هنوز کامل نشده‌اند

- OCR خودکار محور قیمت و زمان، تشخیص قطعی نماد و تایم‌فریم و تبدیل پیکسل به OHLC معتبر.
- کالیبراسیون خودکار چارت و اتصال نهایی Overlay به پیش‌بینی زنده.
- دریافت خودکار XAUS/Corgano در زمان اجرا و موتور جامع انتخاب/جایگزینی چندمنبعی؛ فعلاً کلاینت‌های مرجع مستقل هستند.
- ارزیابی آماری بلندمدت و کالیبراسیون واقعی احتمال‌ها، مدل ML آموزش‌دیده، جریان سفارش و تحلیل اخبار.
- تست عملی اتصال SignalR، screenshot و رفتار چندمانیتوره روی رایانه کاربر.

امتیازهای سناریو فعلی heuristic هستند، نه احتمال‌های آماری کالیبره‌شده؛ خروجی برای تحقیق و آزمایش است و نباید به‌تنهایی مبنای معامله واقعی قرار گیرد. برنامه هیچ سفارشی به کارگزاری ارسال نمی‌کند.

- `trade_journal.py`, `performance_engine.py`, `ml_engine.py`, `tick_flow.py`, `news_engine.py`: ژورنال، ML، فشار تیک و خبر

## حریم خصوصی

پردازش تصویر نمودار روی رایانه محلی انجام می‌شود. screenshotهای انتخاب‌شده برای ژورنال در پوشه `data/screenshots` ذخیره می‌شوند؛ تیک‌ها، کندل‌ها و تاریخچه نیز در SQLite محلی قرار دارند. هیچ تصویر یا داده‌ای به سرویس خارجی ارسال نمی‌شود؛ اتصال‌های بازار فقط برای دریافت داده عمومی/مجاز هستند.

## موتور تحلیل OHLC (مرحله آزمایشی)

ماژول `analysis_engine.py` یک پایه تحلیلی مستقل و قابل‌آزمایش اضافه می‌کند:
- اعتبارسنجی کندل‌های OHLCV و رد داده‌های ناسازگار.
- محاسبه EMA، RSI، ATR و مومنتوم.
- استخراج پیوت‌های ساده حمایت و مقاومت.
- ساخت سناریوهای صعودی/نزولی/خنثی و ۱۵ نقطه تخمینی یک‌دقیقه‌ای.
- خروجی شامل بازه عدم‌قطعیت، سطوح مرجع و محدودیت‌های تحلیل.

**هشدار:** امتیاز سناریوها احتمالات آماری کالیبره‌شده نیست. این ماژول فقط وقتی داده کندل معتبر به آن داده شود کار می‌کند؛ فید BiQuote اکنون کندل‌ها را در SQLite ذخیره می‌کند، اما تطبیق نماد/تایم‌فریم و استخراج OHLC از تصویر هنوز کامل نشده‌اند. از خروجی فعلی برای ورود واقعی به معامله استفاده نکنید.


## ذخیره‌سازی محلی

ماژول `market_store.py` داده‌های کندل و تاریخچه خروجی تحلیل را در SQLite نگه می‌دارد:
- کلید یکتا بر اساس منبع، نماد، تایم‌فریم و زمان کندل؛ به‌روزرسانی بدون تکثیر.
- نگهداری داده Spot و Broker در ردیف‌های جداگانه؛ جلوگیری از مخلوط‌کردن دو نوع قیمت.
- بازیابی کندل‌ها به ترتیب زمانی و ذخیره snapshot پیش‌بینی‌ها.
- دیتابیس به‌صورت محلی ساخته می‌شود و داده‌ای به سرویس بیرونی ارسال نمی‌کند.


## مسیریابی چندمنبعی قیمت

ماژول `feed_router.py` قرارداد اتصال adapterها و انتخاب quote را فراهم می‌کند:
- تفکیک کامل Spot و Broker برای یک نماد.
- رد داده شبیه‌سازی‌شده، قدیمی، زمان آینده، نماد اشتباه و Bid/Ask نامعتبر.
- انتخاب داده تازه‌تر و در صورت برابری، spread نسبی کمتر.
- گزارش منبع‌های ردشده و خطاهای adapter برای عیب‌یابی.

کلاینت‌های BiQuote، XAUS و Corgano در `provider_clients.py` و `biquote_stream.py` اضافه شده‌اند. فقط BiQuote SignalR اکنون هنگام اجرای برنامه به چرخه دریافت تیک متصل است؛ XAUS و Corgano کلاینت‌های مرجع مستقل‌اند و هنوز polling زمان‌بندی‌شده در UI ندارند.


## تشخیص محدوده نمودار از تصویر

ماژول `chart_vision.py` محدوده تقریبی ناحیه کندل‌ها (ROI) و مختصات پیکسلی کندل‌های رنگی را از تصویر BGR استخراج می‌کند. خروجی فقط مختصات تصویر است؛ تا زمان کالیبره‌کردن محور قیمت و زمان و اعتبارسنجی نماد/تایم‌فریم، از این داده‌ها OHLC واقعی ساخته نمی‌شود.


## اتصال رابط کاربری به موتور تحلیل

صفحه «پیش‌بینی ۱۵ دقیقه آینده» اکنون امکان اجرای تحلیل روی آخرین کندل‌های ذخیره‌شده را دارد. نماد، تایم‌فریم و منبع قابل انتخاب‌اند؛ خروجی JSON شامل سناریوها و ۱۵ نقطه تخمینی نمایش داده می‌شود و هم‌زمان در تاریخچه SQLite ذخیره می‌شود. اگر حداقل ۳۰ کندل معتبر وجود نداشته باشد، برنامه پیام کمبود داده می‌دهد. این دکمه داده را از SQLite می‌خواند و درخواست شبکه جداگانه نمی‌فرستد؛ فید زنده BiQuote در پس‌زمینه برنامه کندل‌های کامل را به دیتابیس اضافه می‌کند.


## کلاینت‌های اولیه منابع داده

- `provider_clients.py` یک کلاینت read-only برای BiQuote REST دارد که `allowStale=false` می‌فرستد و فقط پاسخ دارای Bid/Ask، زمان‌دار و بازار باز را به‌عنوان Quote برمی‌گرداند. این REST adapter برای fallback و تست است؛ برای استفاده پیوسته باید SignalR streaming رسمی پیاده‌سازی شود.
- همین فایل XAUS Spot را جداگانه به‌عنوان `SpotReference` می‌خواند. فقط حالت `fresh` پذیرفته می‌شود؛ قیمت indicative mid است و عمداً Bid/Ask جعلی ساخته نمی‌شود.
- کلاینت‌ها فعلاً مستقل از UI هستند و هنوز scheduler، اتصال پایدار SignalR، ذخیره خودکار تیک‌ها و ساخت کندل از تیک را انجام نمی‌دهند.


### جریان زنده BiQuote (SignalR)

ماژول `biquote_stream.py` اتصال SignalR به `/hubs/tick`، ثبت رویداد `ReceiveTick`، اشتراک نمادها، دریافت Bid/Ask و reconnect خودکار را فراهم می‌کند. از REST polling برای حلقه زنده استفاده نمی‌شود؛ REST adapter فقط fallback دستی است. این کلاینت به چرخه عمر UI متصل شده و در thread جداگانه اجرا می‌شود؛ تست CI از اتصال جعلی استفاده می‌کند، بنابراین اتصال واقعی باید روی سیستم ویندوزی و در ساعات باز بودن بازار آزمایش شود.


### اتصال خودکار جریان داده به برنامه

در زمان اجرای برنامه، کلاینت BiQuote در thread جداگانه شروع می‌شود. تیک‌های تازه XAUUSD از اعتبارسنجی عبور می‌کنند و به سازنده‌های M1/M5/M10/M15/H1/H4 می‌روند؛ فقط کندل کامل‌شده در SQLite ذخیره می‌شود. داده‌ها بر اساس منبع و نماد جدا نگه داشته می‌شوند. هنگام بستن پنجره، اتصال و thread به‌صورت کنترل‌شده متوقف می‌شوند.

این اتصال فقط به منبع BiQuote متصل است؛ XAUS فعلاً مرجع مستقل Spot است و در محاسبه کندل Bid/Ask وارد نمی‌شود. در بازار بسته، یا هنگام قطع اینترنت، برنامه قیمت قدیمی را به‌عنوان تیک زنده قبول نمی‌کند.


## ساختار بازار، حمایت و مقاومت

ماژول `structure_engine.py` حمایت/مقاومت استاتیک را به شکل ناحیه، جدا از خطوط روند داینامیک مبتنی بر پیوت‌ها محاسبه می‌کند. ناحیه هم‌پوشانی احتمالی بین زون‌های استاتیک با اولویت واکنشی بالا علامت می‌خورد، اما صراحتاً `standalone_signal=false` دارد و بدون تأیید ساختار/رفتار قیمت سیگنال ورود نیست. این خروجی اکنون در سرویس تحلیل ذخیره می‌شود.


## تصویرسازی پیش‌بینی روی دسکتاپ

- `chart_projection.py` با دو نقطه قیمت/مختصات عمودیِ تأییدشده، قیمت را به مختصات صفحه تبدیل می‌کند و مسیر ۱۵ نقطه‌ای و باند عدم‌قطعیت را به مختصات پیکسلی می‌برد.
- `forecast_overlay.py` پنجره شفاف، همیشه‌بالا و mouse-through برای رسم مسیر و باند را فراهم می‌کند.
- برای جلوگیری از رسم گمراه‌کننده، Overlay تا وقتی کالیبراسیون محور قیمت و مقیاس زمان معتبر فراهم نشود، نباید نمایش داده شود. OCR خودکار اعداد محور، کالیبراسیون خودکار، اتصال Overlay به چرخه اصلی UI و اعتبارسنجی هم‌ترازی با چارت هنوز تکمیل نشده‌اند.


## ژورنال معاملات دستی

صفحه «ژورنال معاملات» و ماژول `trade_journal.py` ثبت دستی Long/Short، ورود، حد ضرر، حد سود، یادداشت و مسیر تصویر چارت را در SQLite فراهم می‌کنند. اگر پنجره چارت شناسایی شده باشد، دکمه تصویر، screenshot محلی همان پنجره را در `data/screenshots` ذخیره و به رکورد پیوند می‌دهد. با انتخاب یک ردیف و واردکردن خروج، نتیجه به‌صورت مضرب ریسک (R) محاسبه می‌شود. این بخش هیچ سفارش معاملاتی ارسال نمی‌کند.


## گزارش عملکرد ژورنال

ماژول `performance_engine.py` و صفحه «گزارش عملکرد» تعداد معاملات بسته‌شده، برد/باخت/سر‌به‌سر، نرخ برد، میانگین R، expectancy، profit factor، حداکثر افت سرمایه بر حسب R و منحنی تجمعی R را از معاملات ژورنال محاسبه می‌کنند. این گزارش به‌جای ادعای سود پولی، از مضرب ریسک استفاده می‌کند.


### Corgano spot reference و محدودیت درخواست

کلاینت `CorganoSpotAdapter` قیمت مرجع XAU spot را از endpoint رسمی دریافت می‌کند، timestamp را تا حداکثر ۱۸۰ ثانیه بررسی می‌کند و به‌خاطر سقف اعلام‌شده ۵۰۰ درخواست روزانه، نتیجه را حداقل ۲۴۰ ثانیه cache می‌کند (حداکثر نظری ۳۶۰ درخواست در ۲۴ ساعت). متن و لینک attribution اجباری را نیز همراه داده برمی‌گرداند. این منبع فقط قیمت indicative است و وارد Bid/Ask یا ساخت کندل بروکری نمی‌شود.


### مقایسه مستقل قیمت‌ها

`reference_comparator.py` اختلاف mid بروکر با قیمت‌های مرجع XAUS/Corgano را بر حسب basis point گزارش می‌کند، داده قدیمی یا نماد اشتباه را رد می‌کند و اختلاف غیرعادی بین منابع مرجع را علامت می‌زند. این مقایسه صرفاً کنترل کیفیت است؛ قیمت Spot جای Bid/Ask بروکر را نمی‌گیرد و هیچ منبعی بدون اعتبارسنجی جایگزین منبع دیگر نمی‌شود.


## صفحات تکمیلی داشبورد

- «حمایت و مقاومت» ساختار استاتیک/داینامیک را از آخرین داده‌های ذخیره‌شده نشان می‌دهد.
- «سناریوهای بازار» امتیاز سناریوها، سوگیری جهت‌دار و ۱۵ نقطه تخمینی را نمایش می‌دهد.
- «تاریخچه پیش‌بینی‌ها» آخرین snapshotهای ذخیره‌شده در SQLite را بازیابی می‌کند.
- «گزارش عملکرد» و «ژورنال معاملات» از یک دیتابیس محلی مشترک استفاده می‌کنند.


## ساخت فایل اجرایی ویندوز

روی Windows و با نصب Python 3.12، از ریشه پروژه اجرا کنید:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\build_windows.ps1
```

خروجی پوشه‌ای در `dist/ComprehensiveApp/` ساخته می‌شود. همین build از GitHub Actions نیز با اجرای دستی workflow «Windows executable» یا push کردن tag با الگوی `v*` قابل اجراست. فایل اجرایی هنوز باید روی سیستم مقصد از نظر فید زنده، capture و Overlay آزمایش شود.
